## 用户已确定的约束

1. 原文的所有表述均不得改动。只允许将 Markdown / HTML 标记转换为 LaTeX 语法，以及进行这些转换所必需的转义、分组和兼容处理。
2. 不得润色、纠错、增删、概括、翻译或重排原文。数学结论、证明、变量、标点、代码、注释、文件名、链接文字和待补充标记同样受此约束。发现疑似错误时单独向用户说明，不在转换中修正。

4. 不得依据段落内容自行增加“定义”“定理”“证明”“注意”等原文没有的标签，不得把一般高亮擅自重新分类为定理环境。
5. 用户明确允许的例外：代码块前的文件名移入浅色标题栏后，省略其后用于引出该代码块的冒号（`：` 或 `:`）；不删除其他正文冒号，不重复显示文件名。
6. 用户允许将含义明确的数学快捷命令直接展开为等价的标准 LaTeX 写法，例如 `\N` → `\mathbb{N}`，具体见 C18；不因此改变数学含义。
7. 如果无法确定某段文本中的符号是标记还是字面内容，先核对上下文；仍有歧义时一次只向用户提出一个问题。

## 逐项问题与转换方案

### C01 标题、原编号与自动编号（已确认）

**问题：** 原稿最高层标题已经包含 `0xPQ`，普通 LaTeX 标题命令会额外生成编号。

**方案：** 各级标题使用不带星号的标题命令，标题文字逐字保留；在导言区统一设置：

```latex
\setcounter{secnumdepth}{-1}
```

此设置只控制章节标题的自动编号，覆盖当前使用的 `section`、`subsection`、`subsubsection`、`paragraph` 层级；不关闭公式、图、表或有序列表的编号。其他对象是否编号按各自转换规则处理，不由本条额外增加或取消编号。

| Markdown | LaTeX |
| --- | --- |
| `# 0x11 基础 Misc` | `\section{0x11 基础 Misc}` |
| `## 常用公式` | `\subsection{常用公式}` |
| `### 日期公式` | `\subsubsection{日期公式}` |
| `#### 算法一：分治 NTT` | `\paragraph{算法一：分治 NTT}` |

上述层级是语法映射；标题是否独占一行及其外观以后决定。原文没有编号的次级标题不新增编号。不得把目录名自动生成为新增的正文标题，也不得在文件名中已有的编号之外再给显示标题追加编号。

### C02 标题的目录登记与链接定位（已确认）

**问题：** 星号标题默认不进入目录；逐个手动登记目录会重复书写标题文字，容易造成正文与目录不一致。内部链接还需要唯一、稳定的定位标识。

**方案：** 使用 C01 规定的不带星号的标题命令，并通过全局 `secnumdepth` 关闭标题自动编号。在导言区加载 `hyperref`，由 LaTeX 和 `hyperref` 自动生成目录项与链接目标，不为普通标题重复添加 `\addcontentsline` 或 `\phantomsection`。目录实际显示深度由 `tocdepth` 独立控制，留待后续排版配置决定。

需要作为原文内部链接目标的标题，在标题命令后设置唯一、稳定的 `\label`，标签包含所属 `0xPQ` 编号。例如：

```latex
\section{0x11 基础 Misc}
\label{sec:0x11}

\subsection{常用公式}
\label{sec:0x11-common-formulas}
```

同名标题可以存在，但显式标签必须不同；不单独以标题文字作为标签唯一性的依据。原文内部链接转换为 `\hyperref[标签]{原文链接文字}`，例如 `\hyperref[sec:0x11-common-formulas]{原文链接文字}`，不得改变链接文字或自行新增引用。

不得利用 `\ref` 推导标题中手写的 `0xPQ`，因为它读取的是 LaTeX 计数器而非标题文字。只有原文链接文字与完整标题一致时，才可使用 `\nameref{标签}`。不增加可见标题文字。

### C03 粗体与斜体（已确认）

**问题：** Markdown 强调标记需要转换，正文与数学内容可能混合。

**方案：** `**粗体**` 或确认为强调标记的 `__粗体__` 转换为 `\textbf{粗体}`；`*斜体*` 或确认为强调标记的 `_斜体_` 转换为 `\emph{斜体}`。公式内容不随外层文字加粗而改写：`**$s$ 的周期**` 转换为 `\textbf{$s$ 的周期}`。原有 `\boldsymbol` 等数学命令保留。

`\emph` 表示原有强调语义，具体字体由排版层决定；不主动给原文增加强调。HTML 的 `<em>文字</em>` 转换为 `\emph{文字}`，`<i>文字</i>` 转换为 `\textit{文字}`。中文是否显示为倾斜字形由后续字体配置决定。

### C04 高亮（已确认）

**问题：** 原稿广泛使用扩展语法 `==内容==`，其中还可能包含公式与粗体，不能简单丢弃标记或统一改成粗体。

**方案：** `==内容==` 转换为 `\Highlight{内容}`。例如 `==字符串哈希==` 转换为 `\Highlight{字符串哈希}`。命令保留“原文高亮”的含义，必须容纳普通文字、行内公式及嵌套命令；高亮按用户补充采用不可拆分的短语框，支持内部粗体和行内公式，不要求长段落自动换行。已确认外观接近 HTML `<mark>`：`#FFFF00` 背景，不额外增加水平或竖直间距。

`\Highlight` 是已确认的项目自定义命令，已在 `preamble/mystyle.tex` 重新实现，并在 `preamble/tests/mystyle/highlight.tex` 检验；它不是 LaTeX 内置命令。

### C05 删除线与未完成内容（已确认）

**问题：** 删除线可能被误当成应该删除的内容；空章节也可能被迁移工具过滤。

**方案：** `~~待填坑。~~` 转换为 `\sout{待填坑。}`（依赖 `ulem`，加载时采用 `normalem`，避免改变普通强调的语义）。所有“待填坑。”、空章节标题、仅有名称的条目均保留。

当前删除线内容都是普通文字；若以后遇到跨公式或复杂块结构的删除线，单独处理，不将复杂内容直接塞入未经验证的 `\sout`。

### C06 标记嵌套与字面符号（已确认）

**问题：** 原稿包含高亮套粗体、HTML 套粗体，以及不成对的字面星号。

**方案：** 按原有嵌套关系递归转换：`==**连续点值**的拉格朗日插值==` 转换为 `\Highlight{\textbf{连续点值}的拉格朗日插值}`。不要用多轮全局字符串替换破坏边界。

原稿 `### *DFT 与 IDFT 的矩阵角度` 中的 `*` 没有配对，是标题文字，转换为 `\subsubsection{*DFT 与 IDFT 的矩阵角度}`。类似 `## *转置原理` 也保留可见星号。

### C07 行内代码（已确认）

**问题：** 行内代码中存在 `__int128`、`#`、`$`、`^` 等 LaTeX 特殊字符；直接套用 `\texttt` 会导致语法错误或字符消失。

**方案：** 行内代码转换为 `\texttt{经过文本转义的原内容}`，例如：

| Markdown 内容 | LaTeX |
| --- | --- |
| 行内代码 `__int128` | `\texttt{\_\_int128}` |
| 行内代码 `#` | `\texttt{\#}` |
| 行内代码 `$` | `\texttt{\$}` |
| 行内代码 `^` | `\texttt{\textasciicircum{}}` |
| 行内代码 `std::stable_sort()` | `\texttt{std::stable\_sort()}` |

有连续空格、制表符等必须逐字保存的内容时，使用可保留空白的行内 verbatim 方案；普通正文可用 `\verb|原内容|`，分隔符必须不出现在内容中。标题或其他命令参数中不得直接使用不兼容的 `\verb`，应采用经过验证的参数兼容命令。不得把代码中的 `$...$` 解释成公式。

### C08 围栏代码块与语言标签（已确认）

**问题：** 围栏内部也有 Markdown / HTML / LaTeX 看起来相似的符号，必须作为代码原文处理。

**方案：** 所有行间代码块统一使用 `minted` 呈现；此要求不包括 C07 的行内代码，C07 保持原方案。前面明确指明文件名的代码块按 C09 使用基于 `minted` 的文件插入封装；其余代码块直接内嵌到 `minted` 环境：起始围栏 `c++` 对应 `\begin{minted}{cpp}`，`bash` 对应 `\begin{minted}{bash}`，`makefile` 对应 `\begin{minted}{make}`，结束围栏对应 `\end{minted}`。二者之间的代码原样保留。

代码渲染配置应禁用数学转义、TeX 注释解释和自定义转义入口（`mathescape=false`、`texcomments=false`，不启用 `escapeinside`）。不自动去缩进、不格式化、不改语言、不修改注释；尤其保留 Makefile 的制表符。高亮配色、边框和行号不在本规则中决定。

### C09 引用独立代码文件（已确认）

**问题：** 部分原稿代码块同时存在独立 `.cpp` 文件，直接引用可能引入不同版本，或者丢失代码前面的说明。

**方案：** 如果行间代码块前面明确指明文件名，将文件名原样移入代码块的浅色标题栏，并通过统一接口引用对应代码文件。标题栏承担原文件名高亮的作用，不在正文重复写 `\Highlight{文件名}`；省略原文件名后用于引出该代码块的冒号。例如 `==0x11 日期公式.cpp==：` 及其代码块转换为：

```latex
\InputCode{cpp}{contents/0x10 基础/code/0x11 日期公式.cpp}
```

`\InputCode{语言}{路径}` 已在 `preamble/mystyle.tex` 重新实现，并在 `preamble/tests/` 独立检验；使用 `tcolorbox` 组织标题栏、由 `minted` 呈现代码。默认从路径中提取文件名作为标题；原文显示名称与实际文件名不同时，使用 `\InputCode[原文显示的文件名]{语言}{路径}` 保留原文。语言参数独立于路径，支持 `cpp`、`python`、`bash`、`make` 等 minted 语言标识，不为各语言重复定义接口。

**已确认并实现的外观：** 标题栏为浅灰 `#F2F2F2`，盒子采用 `0.4pt` 黑色边框和直角；代码区白底、统一内边距。语言相关的语法主题、字号、行号和折行交给 `\setminted[语言]{...}` 设置；跨页时续页不重复标题。

前面没有明确指明文件名的代码块，保留原代码并直接插入 C08 的 `minted` 环境；即使存在内容相同的独立文件，也不自动改为文件引用。语言参数沿用 C08 的映射。

引用前核对独立文件与原代码块内容逐字符一致（允许统一 CRLF / LF 文件行结束符）；不得忽略缩进、空行、注释或尾随空格来掩盖差异。文件缺失时，从原代码块原样建立对应文件；已有文件内容不一致时，报告差异并由用户确定处理方式，不擅自覆盖文件或引用不同版本。

除上述引导冒号外，文件名文字、其后的说明和代码块顺序均保留，不额外重复生成代码标题。代码路径按 C25 统一写为相对于项目根目录的路径；`\InputCode` 不自动添加章节目录前缀。

### C10 普通文本中的特殊字符（已确认）

**问题：** LaTeX 会将普通文本中的特殊字符当成控制语法。例如原文 `15~16 位` 中的波浪线会消失并变成不换行空格。

**方案：** 仅在普通文本和 C07 的转义型行内代码中按以下规则处理：

| 原字符 | LaTeX |
| --- | --- |
| `#` | `\#` |
| `$` | `\$` |
| `%` | `\%` |
| `&` | `\&` |
| `_` | `\_` |
| `{`、`}` | `\{`、`\}` |
| `~` | `\textasciitilde{}` |
| `^` | `\textasciicircum{}` |
| 字面反斜杠 | `\textbackslash{}` |

因此 `15~16 位` 转换为 `15\textasciitilde{}16 位`，不改成破折号或汉字“至”。数学环境、verbatim 环境、LaTeX 命令和路径参数分别处理，不能套用普通文本的全局转义。先识别原 Markdown 的转义，再进行一次 LaTeX 转义，避免双重转义。

### C11 段落、软换行与硬换行（已确认）

**问题：** Markdown 源文件的换行并不全是可见换行；机械替换为 `\\` 会改变句子结构。

**已确认：** 不同段落之间直接空一行隔开，不改写为 `\par` 命令。

**方案：** 同一段落中的源码软换行保持软换行语义，不插入显式换行。行尾两个空格所表示的硬换行，以及以后出现的 `<br>` / `<br />`，在普通文本中转换为 `\newline{}`。

不得用 `\\` 代替所有段落分隔，不通过删空格粘连英文词语。代码、数学环境中的换行使用各自规则；纯空白行的数量不用于推测额外的排版留白。

### C12 无序列表与嵌套层级（已确认）

**问题：** 原稿的 `-` 列表含多层嵌套，条目中还存在段落、公式和 HTML。

**方案：** 列表转换为 `\begin{itemize}` / `\end{itemize}`，每个条目的标记转换为 `\item`；子列表放入对应 `\item` 内的下一层 `itemize`。保留条目顺序和条目原文，不改成连续正文。

条目后的公式和续段先核对原稿归属，再放入相应条目。不要仅凭公式前有空行就结束条目，也不要把原本独立的段落自动吸入上一条目。缩进或原编辑器渲染存在歧义时，向用户确认具体一处。

### C13 有序列表与字面编号（已确认，预备规则）

**问题：** 自动递增可能改变原文中明确列出的序号；“求法 1”等文字也可能被错误识别为列表语法。

**方案：** 真正的 Markdown 有序列表转换为 `enumerate`，保留其呈现的起始编号及层级；例如从 `3.` 开始的顶层列表可设置 `\setcounter{enumi}{2}` 后写 `\item`。若序号是需要精确保留的字面标签，使用 `\item[3.]` 等显式标签，避免自动重编号。

原文“求法 1”“算法一”“操作 1”若属于标题或正文，则原样保留在相应标题或正文中，不转换为自动序号。当前扫描未发现需要执行本条的有序列表。

### C14 引用块（已确认）

**问题：** `>` 引用内部包含多段正文、列表以及多行数学环境，逐行转换会拆散结构。

**方案：** 连续引用块整体转换为自定义的 `\begin{quoteblock}` / `\end{quoteblock}`，去掉每行仅用于引用层级的 `>` 前缀，再递归转换内部内容。引用中的空行保留为段落分隔；`> - 条目` 在 `quoteblock` 内生成 `itemize`，`> $$` 在 `quoteblock` 内生成独立公式。例如：

```latex
\begin{quoteblock}
原文第一段。

原文第二段，包含 $公式$。
\end{quoteblock}
```

`quoteblock` 是项目自定义环境，已在 `preamble/mystyle.tex` 重新实现并在 `preamble/tests/mystyle/quoteblock.tex` 独立检验。已确认外观为 `#F7F7F7` 浅灰背景、左侧 2 pt `#777777` 竖线、直角、2 mm 内边距，支持跨页；不重定义或修改标准 `quote` 环境。转换正文时不写入颜色、边框或间距参数。

原稿中的“简单推导”“By the way”等仍是原文文字，不因处在引用块中就被改为其他标题。当前预计不会出现 `quoteblock` 嵌套，未将嵌套块自身跨页列为要求；如转换时发现嵌套引用，先单独报告。环境已检验多段正文、列表、公式和跨页处理。

### C15 行内数学公式（已确认）

**问题：** 原稿的数学内容本身已经使用 TeX 语法，二次转换可能损坏下标、条件和命令。

**方案：** `$公式$` 保留为 `$公式$`，除 C18 已确认的快捷命令等价展开外，只转换其外部的 Markdown / HTML 标记。保留公式内的其他命令、变量、上下标、括号、运算符、标点和顺序，不统一 `O` 与 `\mathcal{O}`，不把 `\mathrm` 改为 `\operatorname`，不改写数学结论。

代码中的美元符号、转义的字面美元符号必须先排除。

### C16 独立公式与自动公式编号（已确认）

**问题：** Markdown 的 `$$...$$` 应转换为文档中的独立数学环境，同时避免产生原文没有的公式编号。

**方案：** `$$公式$$` 转换为以下源码形式，起始定界符 `\[`、公式内容和结束定界符 `\]` 分别独立成行，不写成单行 `\[公式\]`：

```latex
\[
公式
\]
```

公式内部原有的多行结构按 C17 处理，不强制压成一行。原有 `cases`、`bmatrix`、`aligned` 等数学环境及内部内容保留，不额外套用带编号的 `equation` / `align`。

若以后遇到原稿已有的显式 `\tag{...}`，保留原标签，选择支持它的环境；不得自动给其余公式编号。

### C17 独立公式中的多行换行（已确认）

**问题：** 原稿有些 `$$...$$` 内直接用 `\\` 分行，没有 `aligned` / `gathered`。只把外层改成 `\[...\]` 不能可靠保留这些分行。

**方案：** 若存在数学顶层的 `\\` 且没有顶层对齐标记 `&`，添加 `gathered` 包装：

```latex
\[
\begin{gathered}
A \\
B
\end{gathered}
\]
```

若原文已有顶层 `&`，使用 `aligned` 并保留原对齐点。已有完整的 `aligned` / `cases` / 矩阵环境时不重复包装。判定时区分环境内部与顶层的 `\\` 和 `&`；不为追求对齐新增原文没有的数学符号，也不重排公式。数学环境中仅用于源码分隔的空白行可移除，保留显式数学换行与文本参数中的内容。

### C18 数学快捷命令的等价展开（已确认）

**问题：** 原稿使用 `\N`、`\Z`、`\R` 等快捷命令，裸 LaTeX 中未必有定义。

**方案：** 直接在公式源码中展开含义明确的快捷命令，不保留这些别名，也不在公共兼容层为其新增定义：

| 原命令 | 转换结果 |
| --- | --- |
| `\N` | `\mathbb{N}` |
| `\Z` | `\mathbb{Z}` |
| `\R` | `\mathbb{R}` |

这是用户允许的等价语法转换，不得改变集合含义、变量、上下标或其余公式结构。替换时按完整命令识别，不将较长命令中的同名前缀替换，也不处理代码中的同名字面内容。其他快捷命令先确认原含义与标准写法，再进行等价展开；含义不明时逐处列出并询问用户，不自行猜测或新增兼容别名。

`\color`、`\text`、`\boldsymbol`、`\operatorname`、`\brace` 等已有可用命令不因本条统一改写；所需功能通过必要宏包支持。不得利用“修复编译”修改公式含义，语法缺损或无法确认的等价处理应单独向用户说明。

### C19 HTML 颜色（已确认）

**问题：** 原文 `span` 颜色可能包住普通文字、公式或一个单词的一部分。

**方案：** `<span style="color:blue">内容</span>` 转换为 `\textcolor{blue}{内容}`；`red`、`black`、`purple` 同样原样传入。内部再执行 Markdown 转换，颜色作用范围不扩大到后文。

例如 `<span style="color:black">j</span><span style="color:red">iangly</span>` 转换为 `\textcolor{black}{j}\textcolor{red}{iangly}`，中间不加空格。颜色名称保留原含义，具体色值的 CSS / LaTeX 兼容由后续呈现层核对，不在本次选择新的配色。公式内已有的 `{\color{blue}...}` 原样保留。

### C20 HTML 字号及其嵌套（已确认）

**问题：** HTML `<font size="6">` 的 `6` 是 HTML 字号等级，不能直接当作 LaTeX 的 6pt。

**方案：** HTML 字号暂不转换为 LaTeX 字号命令，交由最终审稿人处理。正文仅转换标签内部的内容及其他标记，不加入字号包装命令；将原字号属性及作用范围保留在源码注释中，避免丢失审稿依据。例如：

```latex
% 待最终审稿：原 HTML <font size="6"> 开始
\textcolor{purple}{\textbf{详细的使用手册位于代码注释之中！}}
% 原 HTML </font> 结束
```

不新增 `\SourceFontSize` 命令，不擅自指定 `\Huge` 或具体字号，不把原 HTML 标签作为可见正文输出。原文文字、颜色和强调关系仍按相应规则保留。

### C21 外部链接（已确认）

**问题：** Markdown 链接有独立的显示文字和目标地址，公式中的 `[x^n](...)` 又可能被误识别为链接。

**方案：** `[zak 的博客](https://www.cnblogs.com/zkyJuruo/p/18809573)` 转换为 `\href{https://www.cnblogs.com/zkyJuruo/p/18809573}{zak 的博客}`，保留显示文字、目标及句末标点。先保护数学环境，再识别 Markdown 链接。

以后若出现裸 URL，可用 `\url{原地址}`；内部链接只将目标映射为新的文件或锚点，显示文字不改。URL 参数使用适合 `hyperref` 的转义，不能用普通文本替换规则破坏地址，也不能自行缩短或更换目标。

### C22 图片、外部资源和缩放信息（已确认）

**问题：** 原稿的两个 HTML 图片使用远程 URL，带 `zoom:67%` 或 `zoom:50%`；CSS zoom 与 LaTeX 的图片自然尺寸并无已知的一一对应关系。

**方案：** 图片内容保持原样，后续转换时将可获取的原图保存为本地资源，再通过 LaTeX 图片命令引用。原 HTML：

```html
<img src="https://cdn.luogu.com.cn/upload/image_hosting/tmzjcvie.png" style="zoom:67%;" />
```

直接转换为 `\includegraphics{本地原图路径}`，不添加缩放参数或自定义图片包装命令。原 `zoom:67%`、`zoom:50%` 等缩放信息暂不应用；将原 URL 和缩放属性保留为源码注释或资源映射元数据，供后续审稿参考，不新增可见说明。不把百分比等同于 `\linewidth` 的比例或擅定物理尺寸。

已有本地图片时先核对是否确为同一张图，不能仅按文件名猜测。远程图片无法获取时报告缺失，不重画、不用其他图片代替。无原始标题时不添加图题、编号或浮动体；本次不把常数表图片重写成表格。

以后出现 `![替代文字](路径)` 时，图片本身由 `\includegraphics{路径}` 表示，替代文字保留为源码元数据或可访问性信息，不自动转成可见图题。

### C23 水平分隔线（已确认）

**问题：** 原稿有单独一行的 `---`，它表示分隔，不是三个字面减号。

**方案：** 确认为 Markdown 分隔线后，转换为 `\Separator{}`，保留分隔位置。此命令等价于 HTML `<hr>`，显示横贯所在容器可用宽度的 0.4 pt `#A0A0A0` 浅灰线，上下各约一行文字间距，不用强制换页代替。代码块、数学环境中的 `---` 不按分隔线处理；如以后出现 Setext 标题，须按上下文先排除标题语法。

### C24 Unicode、标点与不换行空格（已确认）

**问题：** 原稿标题含 `⭐`、`🚩`，还出现 U+00A0 不换行空格；转换工具可能删除、替换或规范化它们。

**方案：** 中文与英文标点、全角与半角括号、引号、大小写及可见 Unicode 字符保持原样。例如 `多项式全家桶⭐`、`质数🚩` 保留原字符，字体缺字留给后续字体兼容处理，不改成其他符号。

正文 U+00A0 可转换为 LaTeX 的 `~` 来保留不换行语义；这与 C10 中普通字面波浪线的 `\textasciitilde{}` 不同。代码中的 U+00A0 保持原字符。发现零宽字符等其他特殊字符时先记录和核对，不批量清除。不自动把 `...` 改成 `\ldots`，不替换直引号、连接号或原文标点。

### C25 中文文件路径与 LaTeX 参数（已确认）

**问题：** 当前文件名包含中文、空格、全角括号及 `[l,r]` 等符号，路径传参错误会使正文或代码缺失。普通 `\input` 不会将工作目录自动切换到章节目录。

**方案：** 根目录的 `main-portrait.tex`、`main-landscape.tex`、`main-code.tex` 分别作为三版入口，从项目根目录启动编译；所有章节、代码和图片引用统一使用相对于项目根目录的路径。例如按当前目录结构：

```latex
% 完整版入口直接引入章节
\input{contents/0x10 基础/0x11 基础 Misc.tex}

% 章节正文中引用代码
\InputCode{cpp}{contents/0x10 基础/code/0x11 日期公式.cpp}
```

图片同样使用 `\includegraphics{相对于项目根目录的实际图片路径}`。章节文件只包含正文，文档类、宏包和 `document` 环境由主文件统一管理。

直接使用标准 `\input` 引入章节，不新增 `\InputChapter` 等章节引入接口，不设置章节目录上下文，也不自动拼接章节路径。C09 的 `\InputCode` 仅保留已确认的代码标题栏与 minted 呈现职责，按传入的根目录相对路径读取文件。

路径参数用完整花括号包围，按文件系统真实名称传入，不把正文显示用的 `\_` 等转义直接写进实际路径。如所选宏包对特殊路径支持不足，应在引用命令层处理并验证，不能为解决编译问题擅自改掉正文中的文件名或原文件名。

### C26 尚未出现的表格、脚注、实体与其他 HTML（已确认，预备规则）

**问题：** 后续内容可能出现本次扫描没有覆盖的语法，工具直接删去未知标记会丢失信息。

**方案：** 预备映射如下；实际出现时先检查能否保持内容和结构：

- Markdown 表格 → `tabular`；列分隔符变成 `&`，行边界变成 `\\`，保留单元格顺序、内容及原有对齐声明，不新增标题或编号。
- Markdown 脚注引用及其定义 → 原引用位置的 `\footnote{原脚注内容}`；重复引用或显式自定义标签需单独保留其关系，不重复复制脚注正文。
- `&amp;` → 字面 `&` → 正文中的 `\&`；`&lt;` / `&gt;` → `\textless{}` / `\textgreater{}`；`&nbsp;` → `~`。实体仅在其应被解析的上下文中解码一次，代码中保持字面原文。
- `<strong>内容</strong>` → `\textbf{内容}`；`<em>内容</em>` → `\emph{内容}`；`<code>内容</code>` → 按 C07 转换；`<pre>...</pre>` → 保留空白的代码环境。

- HTML 注释 `<!-- 内容 -->` → 不渲染的 LaTeX 源码注释，保留注释文本，不转成可见正文。

任务列表、合并单元格 HTML 表格、`details`、脚本、未知属性及其他未列语法先列出实例和等价转换方案供审核，不静默忽略或展开重写。

### C27 语法冲突与解析顺序（已确认）

**问题：** 相同字符在不同上下文中含义不同。代码中的 `#include` 不是标题，数学中的 `&` 是对齐符，`[x^n](A...)` 不是网页链接，C++ 模板的 `<int>` 不是 HTML。
